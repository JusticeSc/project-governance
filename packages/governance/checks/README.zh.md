# @project-governance/checks

[English](README.md) | 中文

## 摘要

只运行仓库为自己配置的命令。公开接口是 `runChecks(repository, policyPath = 'governance-checks.json')`，返回进程退出码而不直接退出。策略是仓库内文件，其 `checks` 对象把名称映射到非空命令字符串。整份策略在第一条命令运行前校验完成，随后按顺序以仓库根为工作目录执行。本包不写目标状态、不从项目文件推导命令，也不自行授予任何执行权限。

## 合同

```js
import { runChecks } from '@project-governance/checks'

const code = runChecks('/path/to/repository') // or runChecks(repository, 'config/checks.json')
```

- `repository` 必须是已存在目录；解析为真实路径，因此同一仓库的合法别名可以使用。
- `policyPath` 为仓库内相对路径；绝对路径只有规范形式仍位于仓库内时才被接受。策略文件或其父目录被符号链接／junction 重定向到仓库外时拒绝，且绝不执行。
- 策略必须是含 `checks` 对象的有效 JSON，至少有一项，且每个值都是非空命令字符串。任何违反都在执行任何命令之前返回 `2`。
- 每条命令通过操作系统 shell 执行，工作目录为仓库根，环境沿用当前进程。输出交由调用方。
- 返回值：`0` 全部配置检查通过；`1` 某检查返回非零状态或被信号终止；`2` 仓库、策略、路径或参数无法校验。
- 由于 shell 是直接子进程，终止命令本身的信号以 shell 的非零状态到达本包；`[observed exit …, signal …]` 行仅在 shell 进程本身被信号终止时给出信号名。两种情形的退出码都是 `1`。

## 已知限制与后续工作

- 不写任何状态：没有结果文件、没有基线、没有 `.governance/` 目录。需要历史的调用方自行保存结果。
- 不解析项目清单，因此无法发现工具链或合成检查；`checks` 为空或缺失是配置错误，不是让工具猜测的信号。
- 策略作者被信任：命令字符串是以当前用户权限运行的任意 shell 命令。不提供沙箱、二进制白名单或命令解析。
- 没有并行、重试、超时或按检查覆盖环境变量；唯一支持的形式是顺序命令字符串列表。
- 检查名称只是输出与失败报告用的标签；除 `checks` 对象的键顺序外，不承载顺序或分组语义。
- 包为 `0.0.0` 的私有包，未发布，也不主张任何远端或发布通道。
