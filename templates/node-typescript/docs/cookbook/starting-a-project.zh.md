# 手册：从模板建立不同业务项目

[English](starting-a-project.md) | 中文

当导出的模板将成为新的 Node.js/TypeScript 项目，而不是另一个插件市场时，使用本教程。内置应用与库是完整可运行的示例，不是必选业务功能。工程规则、开发工作流与检查由项目自身承担；日常开发不需要外部采用 Skill。

## 1. 建立检出环境

从完整导出树开始，包括点目录、已恢复的 `.gitignore` 文件与 `.claude/skills` 链接。直接复制 npm 包的子目录不等于导出。保留 `LICENSE` 与 `SOURCE-LICENSE.txt`：重命名项目不取消复制材料的归属声明。

按[开发环境准备](../development.zh.md#bootstrap-a-new-export)在安装钩子前建立本目录自己的 Git 基线。审查导入文件；基线记录它们的身份，不代表检查通过。没有 shell shim 时，用 `corepack pnpm` 代替 `pnpm`；无需启用全局 shim。依赖和工具链留在当前环境，不借用外层项目。

完成条件：首次导入存在，工作树本地钩子已安装，归档基线验证通过，源码类型检查成功。未单独授权时，不动远端设置或发布。

## 2. 确定业务与归属

说明首次行为、真实输入输出、错误、必须保持不变的用户文件，以及用来证明结果的真实 CLI 或库消费者。I/O 与进程生命周期放在 `apps/<app>/`；可复用的类型化行为归 `packages/<group>/<package>/`。库不依赖应用。除非当前消费者需要独立演进的角色，否则保持一个包。

按完整闭包替换示例：`apps/plugin-market-generator/`、`packages/util/plugin-market-index/`、其测试与 manifest、应用／库地图、格式与 CLI 文档、示例术语、安全声明及启动命令。分组只有仍拥有包时才保留。更新根 `AGENTS.md`（既有 `CLAUDE.md` 仍作其替身）、包指令、架构、开发、测试、README 与贡献页面，使其描述实际项目。也要追踪开发工作流中的入链：可复用审查流程不能继续要求已退出示例的格式 Note。

格式 Note 是有实质内容的已实施决策，不是可随手删除的样板。格式退出时，遵循 [Note 生命周期](../../.agents/skills/dsh-archive-agent-notes/SKILL.md)：完整归档三件套，不改正文，只增加归档元数据，重记 sidecar，并针对真实已提交基线封存。将活动入链修到现行权威；冻结历史不是新业务规范。没有已发布消费者需要时，移除过时的示例升级指南。不要虚构发布历史或把旧决策改写成相反结论。

完成条件：每个保留模块有当前生产方与消费者；活动文档和指令描述新业务，来源归属与有价值的历史完整保留。不把无消费者的示例留在新实现旁，也不将其清成空桩。

## 3. 设置项目参数

| Owner | 设置或维护 |
|---|---|
| 根与成员的 `package.json` 文件 | 实际名称、描述、依赖、仓库元数据和启动器。根拥有所有 pnpm 成员的共享版本与许可证；改 scope 不会绕过任何一项规则。原有归属声明另外保全。 |
| `pnpm-workspace.yaml` | 声明成员与排除项；保留本绑定的 `apps/*` 和 `packages/*/*` 组织。为读取根 workspace 声明的工具保持两处一致。 |
| `tsconfig.host.json`、成员 `tsconfig.json`、测试配置 | 实际编译引用与最近的源码／测试项目，不再引用已删除示例。成员引用其真实 workspace 依赖。 |
| `tsconfig.base.json` | 运行 `pnpm run gen-tsconfig-paths`；生成区将已声明库名映射到实际 `src`，不取决于 scope 或目录拼写。手写别名留在生成区外，且必须指向正确源码。不添加分组通配符。 |
| `scripts/project-policy.ts` | 经审查的源码／产物启动器分类、可执行源码与 bin 分类、有理由的分组无页面豁免、真实跨包 typed lint 导入、翻译仓库根、实际生成的英文页面及适用的仓库引用限制。清退陈旧条目；空例外列表不取消底层规则。 |
| `scripts/package-dependency-policy.ts` | 审查并分类实际跨包使用的运行时导出。删除已退出导出；不以宽泛放行未经审查的依赖来使检查通过。 |
| 文档 manifest 与 `.gitignore` | 当前双语语料、有依据的预算，以及实际生成物、缓存和私有数据的排除项。不以排除作者源码隐藏失败。 |

`typedImportProbe` 选择实际消费者的测试目录，以及真实 workspace 根 API 中一个非 thenable 的运行时导出。构建产物不存在时，lint 合同必须拒绝对该值使用 await，并接受精确恢复。包缺失、类型未解析或文件类别漏检都不能证明类型感知 lint 生效。

保留支持的源码／产物合同：库的 `src/index.ts` 编译为 `lib/types/index.js`，打包为 `lib/index.js`，发布根入口与声明，而不是 `src` 子路径。应用使用 `src/bin.ts`；根源码与构建启动器分别分类。`scripts/` 是工程工具，不承载业务行为。新包分组从分组 README 链接其拥有的 `docs/subsystems/*.md` 页面，或者提供当前有效且有理由的无页面分类。

保留稳定的钩子所有权标记与工具协议标识。它们不是业务名称，修改可能遗弃已安装钩子。不全局替换 `dsh`：包身份与活动合同不同于来源归属、历史记录和隔离测试夹具。

完成条件：workspace 管理器、编译图、别名、依赖分类、启动器与文档描述同一个实际项目。业务替换修改实现及项目拥有的配置，而不是通用检查算法。

## 4. 验证真实行为与交付

修改 manifest 后安装，使 `pnpm-lock.yaml` 记录实际依赖图；后续全新检出用 `pnpm install --frozen-lockfile` 验证。按[开发指南](../development.zh.md#verify-a-change)选择对变更最小充分的检查。完整业务替换触及依赖图、行为、类型、产物、依赖／发布规则与文档，因此各层都需要证据。

- 在没有 `lib/` 时运行源码行为。运行所属行为 spec 与包运行时覆盖率门禁；每个库运行时文件仍要求语句、分支、函数和行四项 100%，不加示例豁免。
- 运行类型感知 lint，包括源码、测试和真实跨包拒绝／恢复。身份变化后运行 workspace 约束与 `verify-package-licenses`；改名后的成员仍须拒绝陈旧版本或错误许可证。
- 用 `pnpm run build` 构建，再运行 `pnpm run hygiene` 与 `pnpm run test:built`。业务所属的 `tests/**/*.built.spec.ts` 仅在产物分面运行；保留真实成功、非法请求和既有用户／输出字节保护。普通 Node 与单独打包的库消费者必须使用发布根入口，不借助源码子路径或私有检出依赖。
- 更新双方语言，重记指定配对并运行 `pnpm run doc-sync`。退役 Note 后再次检查归档。按项目审查流程核对必要性、全部受影响消费者、遗漏和无关改动；工具绿色不能替代判断。

完成条件：请求的输出正确，非法输入因预期机制失败，保护文件未改，声明的产物可脱离源码树运行，且所选检查实际执行。明确报告环境限制与未观察的远端强制；存在工作流配置不等于远端通过。

## 5. 仅凭项目材料继续开发

后续请求沿实际架构、包合同、开发与测试 owner 实施。公开 API 或模块迁移在同一变更中迁移全部源码、测试、类型、启动器、资源与文档消费者；旧路径退出，不留兼容垫片。触发外部可观察破坏条件时遵循升级指南工作流。

另一位贡献者或 Agent 接续前，若项目已有状态 owner，将当前请求、实际改动、已执行命令和剩余限制交回该处，不新增竞争进度数据库。下一执行者应能定位 owner 并运行真实项目，不依赖外部治理 Skill、模板作者私有说明或未分发修正。
