# AGENTS.md — Packages

These package-specific rules supplement the repo-wide [conventions](../AGENTS.md#conventions). A package lives at `packages/<group>/<package>/`, belongs to exactly one group, and is described by its group README and [the package map](README.md).

- **One direction of dependency.** A `util/` package is a library: no I/O, no app state, no registration. The app and higher-level packages depend on it; it never imports them. A business rule belongs to the package that owns the capability, not to a shared utility.
- **The public entry is the built root.** `exports["."]` points at `lib/index.js` with declarations at `lib/types/index.d.ts`. Do not add a `./src/*` subpath or put source files in `files`; a packed consumer uses the built root and this checkout has no source-import contract. Source tests and the `tsx` launcher resolve the package name to `src` through the root `paths` map; that is a development arrangement, not a publication.
- **Export keys have repository-wide meanings.** Across ordinary packages and apps, `.` is the built package entry and `./package.json` is toolchain metadata, not a semantic API. No other key is admitted by this binding. Existing undocumented keys are not precedent: adding one first changes the owning rule and `verify-package-export-keys` policy/check with a reason and the domain owner's confirmation. A browser/plugin host's entry-value restrictions apply only when that host exists; its required approval does not waive this ordinary key rule.
- **Import does not initialize asynchronously.** No top-level `await`, `for await` or `await using` in importable package source. Put asynchronous work in an explicit operation and handle rejection. A shebang program or the source corresponding to a manifest `bin` entry is the executable exception, not permission for its imported modules.
- **Publishable versus private.** A library sets `publishConfig.access: "public"` and a `repository` entry; an app is `private: true`. The version matches the root `package.json`.
- **`src/types.ts` contains types only.** No runtime code, no re-export of an implementation. `LocalizedText` is defined once, in the validator's `types.ts`; every consumer imports it there instead of redeclaring it.
- **ESM everywhere.** `"type": "module"`; use package names across packages and explicit `.ts` specifiers in source-relative imports. The compiler rewrites those to `.js` in emitted JavaScript and keeps declarations resolvable for NodeNext consumers.
- **tsconfig.** Extends `tsconfig.base.json`, sets `rootDir: src` and `outDir: lib/types`, includes `src`, and references its workspace dependencies. Register the package project in `tsconfig.host.json`; `pnpm run constraints` and `build:check` cover the aggregate.
- **Declare dependencies you use.** Workspace dependencies use `workspace:*`; a runtime parser or validator goes in `dependencies`; test-only and type-only tooling goes in `devDependencies`. Undeclared imports fail under the strict pnpm linker.
- **Require a current consumer and need.** Tie every abstraction, option, defensive copy, and compatibility path to a current contract or production caller; otherwise defer it. Configurability does not justify an unsupported default, public operation, format, or imported external concept.
- **Give shared state an owner.** Hang caches and shared values on an object with a lifecycle; a module-level cache, singleton, `globalThis` field, or `Symbol.for` key hides its owner and leaks state between tests.
- **Typed, structured failures.** Expected failures use declared error types with handling-relevant details; preserve causes and keep machine identity separate from display text. Never route handling by parsing a message, and never turn containment into success. An empty `catch` names the error and why.
- **Bound the complete result.** Enforce byte, count, and time limits where the complete emitted value, including metadata, is known; test tiny and exact limits, oversized single chunks, and multibyte counts.
- **Tests live under `tests/`.** Not `src/__tests__/`; a fixture shared by specs lives in a plain support module, never another spec. A new source line needs a behavior test, and coverage is per-file 100% for the package's `src`. Exercise the public entry and the real parser rather than a mock of the package.
- **The package README is the contract.** Follow the [cookbook's README shape and classifications](../docs/cookbook/adding-a-package.md#4-write-the-package-readme), including kind, Summary, Model Experience and durable limitations. A genuinely inapplicable section uses the checker policy's classification and reason rather than an empty heading or an unexplained "none". Update both languages together.
- **No product claims.** A package README or JSDoc does not describe consumers, services, or model behavior that this repository does not contain. State the local contract and link the format owner where the data contract lives.
- **Contracts remain at their declaration.** Every module and non-obvious public export has concise JSDoc; function-like exports have `@param` and `@returns` contracts, including optional-input behavior, failures and lifecycle effects where applicable. Keep inherited member documentation on the declaring member, not duplicated on a re-export. `verify-export-jsdoc` checks form; review checks truth and completeness. UI, remote and derived-state objects additionally follow the [conditional domain rules](../docs/defensive-patterns/conditional-domains.md).
