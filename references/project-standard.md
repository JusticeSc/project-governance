# 项目治理标准

建立、改造或维护项目时使用本标准。主动使用本 Skill 就选择遵循这一体系；不是从规则目录中任选，也不再次认证“是否接受治理”。空项目和已有项目必须达到相同状态，分别按[建立与改造流程](adoption.md#adoption)实施；之后由目标工程自身的AGENTS、开发／测试文档与项目内Skills持续开发。[工程变更流程](change-workflow.md#change-workflow)与各专题供接入核对和本产品维护使用，不成为已接入工程的第二日常入口。

本页拥有项目的共同目标状态；接入参考拥有达到该状态的步骤，各专题仍拥有具体工程义务。目录约定是本产品明确的迁移设计，不冒称来源项目所有工具、数值和布局都可原样套用。满足标准必须看真实内容和执行结果，不能以文件存在、填齐字段或安装成功判定。

<a id="governance-owners"></a>
## 1. 固定职责与项目入口

每个事实只在一个位置维护，其他位置链接。下表规定基础项目入口及职责，**不是完整项目结构或事实类别的封闭枚举**。新项目按此建立，已有项目迁移对应内容并修复入链；完整文档分层按[文档放置](documentation-structure-and-prose.md#tier-placement)及[事实归属映射](documentation-adoption-and-checks.md#migration)落实，实际类别不能只限于下表。旧位置仅保留仍有独立职责的内容，不保留同权威副本，不创建空壳或重复脚本清单。

| 位置 | 必须承担的职责 | 不承担的职责 |
|---|---|---|
| 根 `AGENTS.md` | 短开发入口：规则作用域、代码/文档职责地图、开发与测试入口、事实核对和交付约束 | 详细方法全文、历史流水账、所有专项规则、私有会话记录的必备路径 |
| 根 `README.md` | 面向使用者说明用途、真实能力、运行或消费方式、必要前提与限制；链接架构、开发与测试入口 | 维护者状态、完整测试库存、未运行能力的成功宣称 |
| `docs/architecture.md` | 实际目录职责、模块分组与公开入口、允许的依赖方向、应用装配及新增行为落点；按[结构规范](project-structure.md#structure-map)维护 | 手抄逐文件或依赖库存、类型/实现细节、任务进度和长期理由 |
| `docs/development.md` | 开发环境、依赖准备、实际运行/构建/消费路径、模块职责入口、常规操作及其副作用；命令定义链接真实脚本或工具配置 | 复制所有脚本/模块清单、任务进度、长期决定的副本 |
| `docs/testing.md` | 测试层次、需要观察的外部行为、语料/平台范围、本地与CI分工、运行前提、失败处理和评审盲点；链接实际测试/工作流定义 | 用覆盖率或本地绿色替代行为/产物/平台证据，复制全部测试列表 |

代码按[来源布局与工具链绑定](project-structure.md#structure-placement)组织应用、能力族和包内源码/测试，按[结构演进](project-structure.md#structure-evolution)同步实际消费者及检查/分发图。文档、生成内容、双语、链接和预算按[文档触发索引](documentation.md#reader-triggers)落实；Agent Notes的目录和生命周期按其[唯一owner](agent-notes.md#1-激活与目录)执行，不在基础入口或结构页另抄正文。入口齐全不等于这些专项义务已经完成。

### 任务、状态、理由与历史

- **需求与任务。** 当前任务必须明确预期行为、保持项、范围和可观察验收。任务板、Issue/PR或仓库记录只有能承载这些事实且指向实际实现与证据，才可继续作为唯一 owner；原来存在不等于合规。不合规则原位补齐或迁移，不能保留并行权威。
- **跨会话状态。** 用户要求初始化、暂停/交接、压缩前保存，或同一目标需要多会话/另一位执行者继续时，必须有可读的当前目标、阶段、验收结果、未决、证据位置及一个可执行下一动作。核对当前请求与仓库事实后才能续接，历史成功和旧下一动作不授予新权限。已有合规 owner 则复用；没有时按[状态建立与接续](state-owner.md)建立唯一记录。单会话即时任务在当前交付承载验收，不为多步骤创建另一个状态库。私有维护状态可以在产品树外，但公开产品和使用者不能依赖维护者的私有路径。
- **长期理由。** 实现和普通说明无法解释、后续仍需遵守的重要取舍，必须由唯一决策 owner 保存问题、决定、替代、后果和验证。已有载体只有能按[决策生命周期](decisions.md#supersession-audit)区分提出、实施、拒绝、取代和冻结，并落实相应检查责任时才复用；否则按[Note流程](agent-notes.md#1-激活与目录)建立或迁移。普通局部修改不制造假决定。当前事实仍回到代码/说明，理由不成为第二状态源。
- **事故与历史。** 微妙、系统性、重新发现代价高的失败按[复盘准入](decisions.md#postmortem-admission)保留逃逸机制和修正；普通bug不要求永久复盘。未实施方案只能标为待实施、取代或拒绝，不能当作已完成。冻结历史及首次失败保留，当前入口退出其执行权威；仍约束兼容、安全或重引入的独有理由不得一并丢失。

<a id="governance-runtime"></a>
## 2. 必须可执行的工程保证

所有项目都必须具备真实运行或消费路径、可发现行为回归的测试、可复用检查定义、CI接线和语义评审责任。库通过真实消费者加载或调用来验证，不为了满足“运行”虚构CLI。需要构建的交付物必须验证实际构建/安装产物；`test`返回成功、空语料或一个手工替身都不能代替这些结果。

| 责任 | 必须落实 | 不得冒称 |
|---|---|---|
| 当前变更 | 追全接口双方、生产者/消费者、数据、资源清理、文档和交付物；实现需求并保持明确契约 | 只改一个局部、只列预计文件或规则编号就称完整 |
| 本地检查 | 从完整变更面选择最低充分证据，准备依赖/产物并保留实际结果；类型语言将相关调用方纳入检查图，其他语言也须验证语法、导入及真实消费 | 局部通过代表全仓、全部平台、实际安装或CI通过 |
| CI | 与本地复用规则定义和失败语义，执行声明的广覆盖、产物依赖和支持平台；必需失败、取消或跳过不能被汇总为成功 | 工作流文件存在等于已经运行，平台已强制合并保护 |
| 规则接线 | 新增或修改的机械约束在真实入口观察正常、目标违规被拒绝、精确恢复；相关持续回归留在共享入口，合法近似不误拒 | 临时探针替代持续回归，或要求消费者复制整套上游自测 |
| 独立评审 | 核对必要性、语义、遗漏、额外复杂度、生命周期与证据；作者核实、修正或有据反驳，再复审 | 字段齐全、工具绿灯或模型互相认可代替实质判断 |
| 集成与发布 | 分别核对本地、真实CI、平台保护和人工权限；按实际受权流程集成或发布 | 本地绿色授予远端修改、合并、发布或数据破坏权限 |

测试、检查、阈值、排除和预期结果本身也属于受审变更。失败先修原因，不能删断言、缩小语料、吞退出码、放宽预算或重录错误期望制造通过。未失效的有效证据可以复用，不要求每次本地重演完整CI。

<a id="governance-parameters"></a>
## 3. 固定要求、参数与客观触发

执行者必须将要求绑定到实际文件、命令、对象和负责人。语言、包管理器、平台版本、预算值和具体消费者是输入；它们不能改变要求的作用。[代码布局的语言绑定](project-structure.md#structure-placement)必须有真实工具链原因，完整文档分层及唯一事实/状态/决策职责不得因项目偏好取消，也不能缩为基础入口清单。

按[跨方法影响分析](change-workflow.md#obligation-sweep)追七类方法及持续开发支撑的依赖。存在接口、持久数据、资源、双语、生成内容、包、平台或评审对象，就落实对应要求；没有现成检查工具、项目小、旧制度不同、接入麻烦都不是豁免。客观不存在的对象不凭空制造，但本次拟新增对象及后续必需变更同样计入触发，不能只看基线没有就判未触发。

<a id="governance-status"></a>
## 4. 缺项、阻塞与完成

| 实际情况 | 判断与必须采取的动作 |
|---|---|
| 已触发但缺入口、内容、回归或接线 | **未落实**：在当前任务补齐并验证；分批实施期间仍是未完成，不以渐进采用宣称合规 |
| 已触发且工具/依赖/事实/权限暂不可用 | **阻塞**：写清缺少的前提、已尝试动作、受影响条件和最小解阻动作；暂停依赖该前提的动作，完成其余可达工作，不把阻塞转为通过 |
| 客观没有该对象或变化面 | **未触发**：给出实际依据和重新触发条件；不创造虚假业务功能或假语料 |
| 入口存在、命令退出0或元数据齐全 | 只说明各自已观察结果；仍须核对完整触发义务、真实行为、语义review及相应层证据 |

共同目标状态只有在入口与归属真实可用、全部已触发要求落实、业务保持项成立、实际验证和评审完成、必要接续可执行且没有影响验收的未决时才达成。不得把“尚未获得外部权限”改称本地版完整采用；也不要求修复与本次验收无关的全部历史业务缺陷才能开始任何工作。开始开发不需要先认证接受治理，交付却必须如实区分已完成、未落实和阻塞。
