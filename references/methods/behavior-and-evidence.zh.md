# 行为正确性：让断言能抓住真实回归（3.01–3.10）


本节是综合方法的一页：解释断言、真实入口与可观察证据这一变更面；逐项来源与覆盖见[来源与覆盖](sources-and-coverage.zh.md)。

**一、测试必须能失败在目标回归上，覆盖率只证明行被执行。** 行为变更或缺陷修复的测试要覆盖正常、错误与边界结果，行为改变时同步调整过时测试；断言应指向外部可观察行为——例如“取消后不再产生后续动作”，而不是“函数没有抛错”。只执行一遍代码、或让断言复述实现，会在实现错误时继续通过；为了变绿而降低门槛、接受零测试或用 `--passWithNoTests` 掩盖，都不构成证据。覆盖率按文件达标，是因为一个大文件被充分执行不能抵消一个新文件完全没测；源参数是“纳入范围的包源码逐文件 100%”，目标先核定适用源码、阈值及排除项的理由，重型豁免测试仍须独立运行。局部覆盖还要同时指明测试与受影响源码范围，普通 `test` 不等于覆盖率门禁（3.01、3.02）。

**二、模型或用户看到的输出要靠回放证明，且两类 expected 不能混放。** 非平凡的模型、协议或产品用户可见变更，要在同一变更中更新无密钥的录制会话快照，经项目真实入口和随发布配置回放，并把预期输出 diff 当行为变更审阅；单元测试、mock 或“函数返回值没变”不能替代组装后的完整消息内容、顺序与持久化结果。顶层 `snapshots/` 只放“会话 JSONL 既是回放输入又是持久化预期输出”的案例；**非录制会话驱动的** ARIA、布局、CLI、生成器与普通单元预期留在所属 app、包或脚本的 `tests/expected/`，由所属 `test`、`test:expected` 或 `test:web` lane 执行。会话驱动 Web 的浏览器/ARIA 证据仍随同一 Session 保留，不能按输出形式一概迁出。源要求循环、会话生命周期或事件映射变化时，TypeScript 与 Python SDK 的预期输出在同一 PR 更新，并各自执行对应检查（含 Python keyless CI）；普通 `test` 两边都不覆盖。迁移时按目标实际存在的消费面适配，不能因此免除原仓任一 SDK 的义务（3.03、3.04、3.05）。

**三、真实执行路径与资源所有权不可用 mock 或单跑通过代替。** Provider、浏览器、子进程与内核隔离能力要在真实 API、真实浏览器、真实受限进程上验证：mock 通常不会复现鉴权、内核权限、网络协议或进程启动失败；缺少凭据时必须如实记为未执行，而不是写成通过。测试要自己取得并释放资源，恢复全局状态，关闭服务器后等待其真正退出，再让后续测试复用端口或路径；一个只在单独运行时通过的测试是测试缺陷，不是“CI 不稳定”。跨平台差异应修 fixture 与平台语义，不为消除回放失败扩大 normalizer；normalizer 只处理既定的环境噪声，无差别删除路径或时序会让真实回归一起消失。评审要同时看 fixture 与 normalizer，并在对应平台回放（3.06、3.07、3.08）。

**四、人可见界面要有真实流程证据，并在窄屏、键盘与失败状态下成立。** 产品用户可见 GUI 变更的 PR 要用真实服务器、真实模型轮次录制演示 GIF，并用浏览器测试验证受影响交互；静态截图看不出菜单能否关闭、操作后有无反馈、键盘焦点是否丢失。录制要说明被演示的提交、服务来源、模式例外与是否真实模型轮次；只有用户明确要求 fixture 录制时才按该条件记录，不能在缺凭据或服务器时自行替换。界面评审复用既有组件与视觉 token，检查溢出、触摸、仅图标控件的可访问名称与可触发 tooltip、焦点保持、加载与错误反馈位置；源以 390 CSS px 为验收下限，这是源参数，不是所有产品的默认断点。上述两类都由 UI owner 与评审负责，lint、DOM 断言和截图各自都不充分（3.09、3.10）。
