## 0.2.0

### Changed

- The Node/TypeScript template starts without the unrelated plugin-market application or library. Workspace discovery, project policies, documentation and checks use the project's actual members. Persistence roots follow declared configuration, and union-shape changes still require compatibility review without session-specific exceptions. See the [migration guide](docs/upgrade-guide/v0.1.1/empty-template/guide.md).
- The standalone Skill no longer requires an agent-specific skills symlink. Its `--add-missing` mode preserves existing content and reports a partial installation when conflicts still require reconciliation.
- Template acquisition checks exercise an empty project, discovered app/library workspaces, artifact consumption and clean rebuild instead of the removed example.
- The product check can select Node 24 for the template independently of the product runtime. CI prepares pinned pnpm and locked dependencies; the exported copy uses the source template's prepared pnpm store even across drives. The disposable workspace fixture may fetch registry metadata while Skill installation remains offline.
- Git-backed change-scope tests use the same bounded time allowance as comparable fixture tests.
- The packed smoke copies the installed Skill as regular files, avoiding a Windows Node 22 `cpSync` crash on non-ASCII paths.

## 0.1.1

### Changed

- The project-governance Skill is a self-contained directory that can be copied into a project and installs the fixed template offline without npm workspace dependencies. Existing content and installation conflicts remain protected.

## 0.1.0

### Added

- A project-governance Skill for new-project and existing-project adoption and handoff; canonical rule owners for structure, decisions, evidence, review and handoff.
- A CLI application and three capability packages organised as `apps/<app>` and `packages/<group>/<package>`, with package-owned `src/` and `tests/`.
- Explicit policy execution with complete-plan validation and real-path containment, plus exclusive Skill installation from a single distribution allowlist.
- Markdown, bilingual-record, package-documentation and compiler-backed gates with explicit target contracts and unavailable-prerequisite failures.
- A distributable npm-shrinkwrap.json and an offline smoke path from actual tarball through installed Skill to consumer acceptance, refusal and recovery.
- Shared local check commands and a Windows/Ubuntu, Node 22.19/24 CI definition.
- An independent Node.js and TypeScript template at `templates/node-typescript/`, obtained by copying a real source repository and pruning it to complete product closures: a format-1 index validator package and the generator application that consumes it, with their own pnpm workspace, lockfile, gate graph, documentation, Agent Notes and development Skills. The earlier governance-check reference implementation is preserved outside the product as the pre-cutover snapshot.
- The template's gate graph orders lint before an instrumented coverage lane and selected source-tree scans after it, requires per-file 100% statements, branches, functions and lines over package runtime sources, and runs documentation, Agent Note, structure, build, publint and built-runtime checks. Its review-ownership history suite declares Python 3.10 with `requirements.txt` as a prerequisite and fails rather than reporting a pass without it.
- `export-template` and `check:template` acquire that template from the product's single file allowlist: export refuses an occupied destination without touching its content, and the check installs with the frozen lock, builds the artifact plane in the exported copy and drives the built CLI on an empty source list and on a refused argument that must preserve the previous index.
- A repository-owned static structure gate (`scripts/verify-structure.mjs`, `npm run check:structure`) with root `node:test` regressions over temporary npm/ESM fixtures: declared public entries, package-name imports and published subpaths, workspace declarations, dependency cycles and owning-package test dependencies are checked without a build plane, and the installed-seat smoke rejects a real cross-package private import and accepts exact restoration.
- Template delivery preserves source and tests through actual npm packaging, and the author file `gitignore` holds the ignore rules because npm omits `.gitignore`; export restores only that filename, byte for byte.
- A direct new-project tutorial inside the exported template, with a complete example-replacement closure, one setup owner, explicit project-policy data and business-owned artifact specs; routine development uses the project's own materials rather than an external adoption Skill.
- `install-template` installs the fixed Node/TypeScript template directly into a new or existing project. It preflights conflicts before writing, preserves existing files, and reports paths needing review if safe rollback cannot finish; the installation Skill guides any authorised conflict merge into the actual project.

### Fixed

- The Skill ends after template installation and handoff; daily development, fixes, review and continuation use the target project's own entry points. The separate Skill-seat installer and template development, review and simplification Skills remain available.
- Template project-tree fixtures now select the current working tree's tracked and non-ignored untracked authors, copy their current bytes, and fail with the path of a selected author that disappears or is unreadable instead of skipping it. Linked entries are excluded without being followed, a tracked author matching an ignore rule is refused, and the typed-lint probes write into a per-test private checkout with read-only dependency links, so another spec creating or removing transient files can no longer break a copy or leak probes into the author tree.
- The template's supplemental export-key check now covers declared apps as well as libraries, accepts apps without export maps and rejects stale app policy entries. Workspace-CLI regression covers app rejection, policy registration, library constraints and restoration; provenance and testing documentation distinguish this added checker from the source's reviewed rule and retain domain-owner confirmation as a review responsibility.
- Review maintenance now gates candidates in an isolated checkout, leaves the operator working tree and index untouched during drafting, binds the saved diff to its manifest, and sends version-2 adoption adapters the actual bounded PR patch evidence. Existing adoption adapters must migrate to version 2.
- The template's artifact-hygiene fixture copies tracked and non-ignored working inputs plus declared workspace `lib/` outputs rather than recursively copying ignored local data and caches. It preserves the exclusion of linked files and parent directories and refuses tracked inputs that match ignore rules; unignored files and files inside build-output directories still require care.
- The template's concrete-terms gate excludes pnpm's generated `.pnpm-cache` while continuing to reject ambiguous terms in maintained files; the template's ignore rules also identify this cache as local data.
- The template's package-creation tutorial now includes a package-owned test TypeScript project and explicit product-use classification, preserving separate source, test and artifact planes when adding a workspace library.
- Template distribution excludes local Claude settings while retaining its skills entry. Package-family README kind checks cover both languages, and the unavailable-repository policy is connected to the documentation gate.

- The template's format-1 validator now applies npm's maintained new-package-name rules, rejects unparseable versions and noncanonical npm versions with `MarketIndexError` at the offending path, and preserves parseable Git version strings and build metadata. An upgrade guide covers previously accepted invalid indexes.
- The template's Git index generator now retains release tags with build metadata instead of silently omitting tagged versions from earlier commits. The generation cache identity advances so old negative results are reconsidered under the corrected validation rules; old last-success fallback records are not reused.
- The template's review-ownership gate no longer reports a pass after discovering no test: the discovery pattern now travels as `"test_*.py"`, which `cmd` passes through instead of keeping a single-quoted pattern that matched nothing, and the two fixtures that need a POSIX filesystem or an executable wrapper script skip explicitly on Windows with the missing capability named. Its CI job grants the 90000ms per-test coverage budget the reference repository uses, and its pages list the suite as a tier and name the platform requirement.
- Template commit and automatic merge-commit hooks check affected bilingual pairs in the Git index without changing staged or unstaged content. Template export restores the Claude skills directory link and Claude instruction imports, dispatches through a product-directory alias, and documents its symbolic-link prerequisite. Daily `hygiene` includes publint against built artifacts; setup distinguishes the Windows skips from the complete POSIX suite. Public setup commands use the template's actual interfaces.
- The template's format-1 validator preserves and validates distribution tags and requires a valid explicit `engines.dsh` on every version. The generator retains eligible npm channel mappings and no longer infers compatibility from peer dependencies; a version without an explicit valid range is skipped.
- Direct template compiler entrypoints resolve the workspace's pinned pnpm dependency when no lifecycle entrypoint is present, while lifecycle builds keep their original invocation and child environment. The existing direct-CLI regression now clears case-insensitive environment-key variants on Windows too.
- Template launch examples pass options directly to their pnpm scripts. The pre-push Skill restores the stack-sync post-publication validation and repair path, distinguishes it from ordinary rewrites, and accurately scopes coverage to package runtime sources.
- Explicit hook installation rejects a missing owning repository, an enclosing repository and an unavailable local executable instead of reporting successful non-installation or touching the parent. New-export setup records reviewed initial inputs before hooks are installed; the import is not a claim of passing checks. Existing CI skips, worktrees, aliases and archive protection remain unchanged.
- TypeScript documentation examples compile against workspace APIs again through `doc-typecheck`, documentation sync and CI. Standalone checks prepare contracts; coordinated checks read current declarations after the build. Paired Chinese examples reuse identical checks, archived Notes remain excluded, and the existing opt-out threshold also rejects an ignore-only corpus when at least four eligible blocks exist. `test:docs` keeps its build-free scope.

Export restores every npm-safe `gitignore` in its original directory, so local agent metadata and review-ownership Python caches remain ignored; the template verifier checks the restored names against their author inputs. The publication allowlist excludes generated Python caches from the raw tarball while retaining review source and configuration.
- Restored conditional upgrade guides for externally observable CLI, data-format and published API breaks, including the internal-only exemption, release maintenance, bilingual template and source-derived validator in documentation and CI aggregates. The package map now defers dependency details to the manifest instead of omitting a runtime dependency.
- Template aliases, shared-version constraints and license checks follow declared workspaces instead of the copied package-name prefix. Renamed scoped or unscoped members remain covered; generated source aliases no longer depend on matching directory names. Source and test typed-lint probes discover actual workspace projects, and obsolete source-only generated-document and organization exceptions are no longer default project policy.

### Boundaries

No remote CI result, platform enforcement or independent Agent adoption is certified. Note and approval responsibilities remain required when triggered, but the product's own runtime installs no candidate executor; the template's review-ownership and Note executors belong to the exported template copy. The product's structure gate checks literal specifiers: it leaves computed import/require calls, aliased loaders and dynamic resolution unproven, forbids authored source links, and does not judge semantic quality. TypeScript is that gate's parser dependency, not a product build plane, and the template keeps its own gates. The product does not ship a duplicate knowledge corpus, maintainer state or host-specific hooks. The template is an implemented reference project, not evidence of governance effects on later development or of Skill reproduction; its authored files ship without dependencies, build output or caches, and the Skill installer is unchanged. `check:template` proves acquisition and the built artifact only; the template's complete gate graph runs from its own CI workflow, and a local run observes neither that workflow nor its platform matrix.
